## O que é

O **SecBoxLab** forma profissionais capazes de entender sistemas, identificar riscos, construir segurança, investigar problemas, proteger aplicações e infraestrutura, responder a incidentes, automatizar defesa e trabalhar com IA — sem abrir mão do julgamento técnico.

A proposta não é assistir aulas. É **aprender segurança fazendo o trabalho de um Cybersecurity Engineer**.

O aluno começa com ensino guiado e avança para problemas cada vez menos orientados: primeiro “faça comigo”, depois analise, corrija, decida e, nos labs, investigue o incidente.

---

## O que não é

Não é um curso de hacking, pentest, ferramentas, SOC ou certificação.  
Não é uma plataforma de CTF.  
Não é uma biblioteca de videoaulas.

Pentest, detecção e resposta existem como competências. O centro é **Engenharia de Segurança**.

## Career Path

A progressão descreve competências, complexidade e autonomia técnica. Não é promessa de senioridade de mercado.

```text
FOUNDATIONS
  → Junior Cybersecurity Engineer
    → Mid-level Cybersecurity Engineer
      → Senior Cybersecurity Engineer
        → Specializations
           └── AI Security Engineer
```

| Nível | Foco |
| --- | --- |
| **Foundations** | Computação, Linux, redes, HTTP, Git, Python, cloud, identidade, criptografia e fundamentos de segurança. IA como ferramenta de estudo. |
| **Junior Cybersecurity Engineer** | AppSec, OWASP, IAM, cloud básica, vulnerability management. Executar, identificar, corrigir, documentar. |
| **Mid-level Cybersecurity Engineer** | DevSecOps, threat modeling, cloud, detection, incident response, automação. Integrar segurança à engenharia. |
| **Senior Cybersecurity Engineer** | Arquitetura, risco, platform security, resposta avançada. Decidir, prevenir, priorizar, comunicar. |
| **AI Security Engineer** | Especialização avançada, desbloqueada após maturidade suficiente. Segurança de sistemas AI-native: agentes, RAG, MCP, guardrails. |

Outras especializações (Cloud, AppSec, Detection, Architecture) ficam abertas na arquitetura. Só **AI Security Engineer** existe neste momento.

## IA desde o início

A formação é **AI-native**. IA não é um módulo isolado.

Nos níveis iniciais, ajuda a aprender. Nos intermediários, a investigar e automatizar. Nos avançados, a revisar arquitetura, correlacionar evidências e trabalhar com codebases.

Ferramentas como Claude, Claude Code, ChatGPT, agentes e MCPs fazem parte do ofício. Não substituem fundamentos.

Duas competências distintas:

| Cybersecurity Engineer | AI Security Engineer |
| --- | --- |
| Usa IA para fazer segurança. | Protege os próprios sistemas de IA. |

**IA acelera a investigação. O julgamento continua sendo do engenheiro.**

## Real-World Labs

O diferencial não é hackear máquinas. É **simular o trabalho**.

O aluno recebe ticket, finding, alerta, incidente, pull request, log, CVE ou exposição de secret — e precisa investigar, identificar, priorizar, corrigir, validar, documentar e comunicar.

```text
Alerta → investigação → causa raiz → correção → validação → finding
```

As tecnologias são funcionais. O contexto empresarial é simulado.

---

## Princípios

1. **Prática de engenharia** — segurança se aprende protegendo, investigando e decidindo, não só reproduzindo exploits.
2. **Fundamentos primeiro** — IA acelera, mas não substitui compreensão de sistemas.
3. **Ambientes profissionais simulados** — o laboratório replica rotina de Security Engineering, não só challenges.
4. **Ética e responsabilidade** — atuação com rigor técnico, respeito a limites e uso exclusivamente educacional dos cenários.
5. **Progressão honesta** — o Career Path mede competência. Experiência real de mercado continua necessária para senioridade.
