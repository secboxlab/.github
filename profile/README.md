## O que é

O **secboxlab** forma profissionais capazes de entender sistemas, identificar riscos, construir segurança, fazer pentest, investigar problemas, proteger aplicações e infraestrutura, responder a incidentes, automatizar defesa e trabalhar com IA — sem abrir mão do julgamento técnico.

A proposta não é assistir aulas. É **aprender segurança fazendo o trabalho de um Cybersecurity Engineer**.

O aluno começa com ensino guiado e avança para problemas cada vez menos orientados: primeiro “faça comigo”, depois analise, corrija, ofenda, decida e, nos labs, investigue o incidente.

---

## O que não é

Não é um curso só de hacking, ferramentas, SOC ou certificação.  
Não é uma plataforma de CTF.  
Não é uma biblioteca de videoaulas.  
Não é “aprender prompt para vazar pentest no ChatGPT”.

Pentest faz parte do Career Path. Detecção e resposta também. O centro continua sendo **Engenharia de Segurança**: entender o sistema, ofender, proteger, investigar e decidir.

## Career Path

A progressão descreve competências, complexidade e autonomia técnica. Não é promessa de senioridade de mercado.

```text
FOUNDATIONS
  → Junior Cybersecurity Engineer
    → Mid-level Cybersecurity Engineer
      → Senior Cybersecurity Engineer
        → Specializations
           └── AI Security Engineer
```

| Nível | Foco |
| --- | --- |
| **Foundations** | Computação, Linux, redes, HTTP, Git, Python, cloud, identidade, criptografia e fundamentos de segurança. Primeiro contato com o pensamento ofensivo. IA como ferramenta de estudo — e para aprender a formular o que pedir. |
| **Junior Cybersecurity Engineer** | AppSec, OWASP, IAM, cloud básica, vulnerability management e pentest guiado. Executar, identificar, explorar com escopo, corrigir, documentar. |
| **Mid-level Cybersecurity Engineer** | DevSecOps, threat modeling, cloud, detection, incident response, automação e pentest com mais autonomia. Integrar segurança à engenharia. |
| **Senior Cybersecurity Engineer** | Arquitetura, risco, platform security, resposta avançada e **pentest com IA**. Decidir, prevenir, priorizar, comunicar — e ofender com agentes, sabendo o que pedir, o que restringir e o que validar. |
| **AI Security Engineer** | Especialização avançada, desbloqueada após maturidade suficiente. Segurança de sistemas AI-native: agentes, RAG, MCP, guardrails. |

Outras especializações (Cloud, AppSec, Detection, Architecture) ficam abertas na arquitetura. Só **AI Security Engineer** existe neste momento.

## AI-first

A formação é **AI-first**. IA não é um módulo no fim da trilha. É o modo de trabalho desde o Foundations.

**AI-first** significa partir da IA por padrão: estudar, explicar, investigar, escrever, automatizar e, no estágio avançado, ofender e defender com agentes. Não é esperar o problema ficar pronto para depois “consultar o ChatGPT”.

AI-first também não é terceirizar o raciocínio. O aluno aprende a **entender o sistema o suficiente para saber o que pedir de verdade**. Sem contexto, restrição e evidência, a IA acelera o erro. Com entendimento, ela acelera o engenheiro.

O que se treina:

- formular o problema
- dar contexto, limites e evidência
- revisar o que a IA devolve
- decidir o que entra em produção

Ferramentas como Claude, Claude Code, ChatGPT, agentes e MCPs fazem parte do ofício. Não substituem fundamentos.

No Senior, isso inclui **pentest com IA**: usar agentes para ampliar cobertura ofensiva, sem abrir mão de escopo, evidência e julgamento.

Duas competências distintas:

| Cybersecurity Engineer | AI Security Engineer |
| --- | --- |
| Usa IA para fazer segurança. | Protege os próprios sistemas de IA. |

**IA acelera a investigação. O julgamento continua sendo do engenheiro.**

## Real-World Labs

O diferencial não é hackear máquinas. É **simular o trabalho**.

O aluno recebe ticket, finding, alerta, incidente, pull request, log, CVE, exposição de secret ou escopo de pentest — e precisa investigar, identificar, priorizar, explorar quando o trabalho pede, corrigir, validar, documentar e comunicar.

```text
Alerta → investigação → causa raiz → correção → validação → finding
```

As tecnologias são funcionais. O contexto empresarial é simulado.

## Princípios

1. **Prática de engenharia** — segurança se aprende protegendo, ofendendo com responsabilidade, investigando e decidindo, não só reproduzindo exploits.
2. **AI-first, fundamentos no centro** — partir da IA é o modo de trabalho. Saber o que pedir exige entender o sistema.
3. **Ambientes profissionais simulados** — o laboratório replica rotina de Security Engineering, inclusive pentest, não só challenges.
4. **Ética e responsabilidade** — atuação com rigor técnico, respeito a limites e uso exclusivamente educacional dos cenários.
5. **Progressão honesta** — o Career Path mede competência. Experiência real de mercado continua necessária para senioridade.
